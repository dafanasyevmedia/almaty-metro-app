# Метро Алматы — расписание (Telegram Mini App)

Одностраничное приложение: показывает ближайшую станцию метро по геопозиции
и обратный отсчёт до следующих двух поездов в обе стороны. Данные берутся из
`data/schedule.json`, который раз в сутки обновляется скриптом
`scripts/update_schedule.py` из официального API metroalmaty.kz. Три языка
интерфейса (қазақша / русский / English).

**Работает здесь:** https://dafanasyevmedia.github.io/almaty-metro-app/

> Хотите разобраться в устройстве кода или продолжить разработку (сами
> или с помощью AI-ассистента) — см. [CLAUDE.md](CLAUDE.md). Там —
> архитектура и все неочевидные решения с объяснением, почему они именно
> такие. Этот README — только про то, как запустить и опубликовать.

## Структура проекта

```
index.html                     — всё приложение (разметка + стили + JS, 3 языка)
data/stations.json             — координаты + названия станций (ru/kk/en)
data/schedule.json             — расписание (перегенерируется ежедневно)
data/icon-source.svg           — исходник иконки (для перегенерации favicon)
data/holidays.json             — даты праздников (обновлять раз в год, см. CLAUDE.md)
scripts/update_schedule.py     — скрипт обновления расписания
.github/workflows/update-schedule.yml — автозапуск скрипта раз в сутки
favicon*, apple-touch-icon.png,
web-app-manifest-*.png, site.webmanifest — иконки (сгенерированы на
                                            realfavicongenerator.net)
CLAUDE.md                      — техническая документация для разработки
```

## Проверить локально

```bash
python3 -m http.server 8765
```

Открыть http://localhost:8765 — геолокация в обычном браузере на localhost
обычно работает без HTTPS.

## Обновить расписание вручную

```bash
python3 scripts/update_schedule.py
```

## Публикация — подробная инструкция для новичка

Ниже — полный путь от папки на компьютере до рабочей ссылки в Telegram.
Рекомендуемый способ — **GitHub Desktop**: это приложение с окошками и
кнопками, оно само разбирается с логином на GitHub и не потребует
возиться с токенами в терминале. Терминальная альтернатива — в самом
низу, для тех, кто предпочитает командную строку.

### Шаг 1. Завести аккаунт на GitHub

Если аккаунта ещё нет — [github.com/signup](https://github.com/signup).
Если есть — просто запомните логин и пароль, они понадобятся на шаге 2.

### Шаг 2. Установить GitHub Desktop

1. Скачать с [desktop.github.com](https://desktop.github.com) и установить как обычное приложение.
2. Открыть его. Нажать **Sign in to GitHub.com** — откроется браузер,
   войти под своим аккаунтом и разрешить доступ. Вернуться в приложение.

### Шаг 3. Добавить проект в GitHub Desktop

1. Меню **File → Add local repository...**
2. Указать путь к папке `almaty-metro` (та, где лежит `index.html`).
3. GitHub Desktop скажет, что это ещё не git-репозиторий, и предложит
   кнопку **create a repository** — нажать её.
4. В открывшейся форме ничего менять не нужно (имя уже подставится) —
   нажать **Create Repository**.

### Шаг 4. Опубликовать репозиторий на GitHub

1. В левой панели появится список файлов проекта — это значит, что
   git уже видит их и готов закоммитить. Внизу слева в поле
   "Summary" написать что-нибудь вроде `Первая версия приложения` и
   нажать синюю кнопку **Commit to main**.
2. Сверху нажать **Publish repository**.
3. В открывшемся окне **снять галочку "Keep this code private"** —
   репозиторий должен быть публичным, иначе бесплатный GitHub Pages не
   заработает. Секретов в проекте нет (токен бота тут не хранится),
   так что это безопасно.
4. Нажать **Publish Repository**.

Проект появится на github.com/&lt;ваш логин&gt;/almaty-metro.

### Шаг 5. Включить GitHub Pages (сама публикация сайта)

1. Открыть страницу репозитория в браузере: `github.com/<логин>/almaty-metro`.
2. Вкладка **Settings** (в самом верху, среди Code / Issues / Pull requests / ...).
3. В левом меню — пункт **Pages**.
4. В разделе "Build and deployment" → **Source** выбрать **Deploy from a branch**.
5. Ниже, **Branch**: выбрать `main` и папку `/ (root)`, нажать **Save**.
6. Подождать 1–2 минуты, обновить страницу — сверху появится зелёный
   блок со ссылкой вида `https://<логин>.github.io/almaty-metro/`.

Это и есть ссылка на ваше приложение. HTTPS у GitHub Pages включён по
умолчанию — это важно, без HTTPS браузер не даст доступ к геолокации.

### Шаг 6. Проверить, что сайт работает

Открыть полученную ссылку в браузере телефона, разрешить доступ к
геолокации, убедиться, что показывается ближайшая станция и отсчёт до
поезда.

### Шаг 7. Проверить автообновление расписания

Не обязательно ждать неделю, чтобы убедиться, что автообновление
настроено правильно:

1. На странице репозитория — вкладка **Actions**.
2. Слева — workflow **"Обновление расписания метро"**.
3. Справа — кнопка **Run workflow** → ещё раз **Run workflow** в
   выпадающем окошке. Это запустит скрипт обновления вручную, не
   дожидаясь понедельника.
4. Через 20–30 секунд обновить страницу — рядом с запуском появится
   зелёная галочка (успех) или красный крестик (ошибка, тогда можно
   открыть запуск и почитать лог).

Дальше это будет происходить само каждую неделю, ничего трогать не
нужно.

### Шаг 8. Подключить как Telegram Mini App

1. Если бота ещё нет — открыть в Telegram [@BotFather](https://t.me/BotFather),
   отправить `/newbot` и следовать подсказкам (имя бота, затем логин,
   обязательно заканчивающийся на `bot`). BotFather пришлёт токен —
   он не нужен для этого приложения, можно просто оставить как есть.
2. Отправить BotFather `/mybots` → выбрать своего бота → **Bot Settings**
   → **Menu Button** → **Configure menu button**.
3. Вставить ссылку на GitHub Pages из шага 5, затем ввести текст
   кнопки, например `Расписание`.
4. Открыть чат с ботом в Telegram — рядом с полем ввода сообщения
   появится кнопка с этим текстом. Нажатие открывает приложение прямо
   внутри Telegram.

Геолокация внутри Telegram сначала пробует
`Telegram.WebApp.LocationManager` (нужен относительно новый клиент
Telegram), если недоступно — обычный `navigator.geolocation` браузера,
если и это недоступно — ручной выбор станции из списка.

### Как публиковать изменения в будущем

Когда в коде что-то поменяется:

1. Открыть GitHub Desktop — слева появится список изменённых файлов.
2. Внизу написать короткое описание изменения, нажать **Commit to main**.
3. Нажать **Push origin** сверху.

Через минуту-две GitHub Pages сам пересоберёт сайт — ничего в
настройках Pages трогать не нужно.

<summary>Альтернатива: публикация через терминал (без GitHub Desktop)</summary>

Требует чуть больше шагов, потому что при отправке кода на GitHub
терминал попросит не пароль, а **Personal Access Token** — GitHub с
2021 года не принимает обычные пароли по команде `git push`.

1. Создать пустой репозиторий на github.com → **New repository** →
   указать имя `almaty-metro` → **не** ставить галочки "Add a README" /
   ".gitignore" / "license" (они уже есть локально) → **Create repository**.
2. Создать токен: Settings (аккаунта, не репозитория) → Developer settings
   → Personal access tokens → Tokens (classic) → **Generate new token** →
   отметить галочку `repo` → сгенерировать и скопировать токен (он
   показывается один раз).
3. В терминале, в папке проекта:

   ```bash
   git init
   git add .
   git commit -m "Первая версия приложения"
   git branch -M main
   git remote add origin https://github.com/<логин>/almaty-metro.git
   git push -u origin main
   ```

4. При запросе логина ввести свой GitHub-логин, при запросе пароля —
   вставить скопированный токен (символы не будут отображаться при
   вставке, это нормально).

Токен — секрет уровня пароля: он не должен попадать ни в код, ни в
переписку, ни в файлы репозитория, вводится только один раз в
собственном терминале.

Дальше — шаги 5–8 из инструкции выше (Pages, Actions, BotFather)
одинаковы для обоих способов.

## Известные ограничения

- Расписание статическое (как на официальном сайте) — это не GPS-трекинг
  поездов в реальном времени, а расчёт по таблице интервалов.
- Официальный API metroalmaty.kz не отдаёт отдельное расписание на выходные
  для станции «Абая». Приложение в этом случае не копирует будние интервалы
  (они гуще настоящих выходных), а оценивает выходной интервал по соседним
  станциям — подробности в [CLAUDE.md](CLAUDE.md). Такая станция помечена
  в интерфейсе как "интервалы рассчитаны по соседним станциям".
- Праздничные дни не учитываются (API их не размечает) — в праздники
  интервалы могут отличаться от того, что покажет приложение.
- Английские названия станций — не от метро (у него их нет), а из
  англоязычной Википедии.
